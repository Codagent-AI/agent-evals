# Verification checklist: end-to-end

This is a verification plan, not evidence that the implementation has passed. The approved proposal, design, specs and [test plan](test-plan.md) control the checks. Requirement names refer to the named capability under `specs/<capability>/spec.md`. Integration and end-to-end IDs refer only to the test plan's INT-001 through INT-012 and E2E-001; the real-browser scripts are also named there. Unit/component tests and inspection provide narrower checks where sufficient. No row requires an agent to operate the product or perform a live subjective review.

Original `I-*` and `L-*` IDs are retained together where behaviors overlap; an ID can appear on several rows when its original row contained distinct behaviors. `C-*` rows cover definition requirements omitted by both checklists. Source identifies the behavior's origin, not who strengthened its check. Checks are assertions to execute after implementation; no behavior is marked verified here.
